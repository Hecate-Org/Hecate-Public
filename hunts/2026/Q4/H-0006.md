Adversaries supply crafted `x-middleware-subrequest` HTTP request headers to public-facing Next.js applications to bypass middleware authorization checks and gain unauthorized access to protected endpoints via CVE-2025-29927.

Tags: exploit, nextjs, auth-bypass, cve-2025-29927, header-injection  

A critical authorization bypass vulnerability (**CVE-2025-29927**) exists in Next.js middleware handling. In unpatched Next.js applications (all versions prior to 14.2.25 and 15.0.0-rc.5), the routing engine uses an internal HTTP header—`x-middleware-subrequest`—to detect recursive middleware calls. When an external client presents this header in incoming requests directed at protected endpoints (e.g., `/api/admin/*`, `/dashboard/*`), Next.js skips middleware execution entirely, processing the request as if authentication and authorization had already been approved.

According to VulnCheck KEV and EPSS telemetry (99.22% probability), this vulnerability is actively weaponized and exploited in the wild by threat actors seeking initial access to cloud and enterprise web environments.
