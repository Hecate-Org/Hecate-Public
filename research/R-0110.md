## 1. System Research: How It Works

### Summary
The Linux kernel's IPv4 TCP stack handles connection setup by allocating a request socket during the SYN handshake, which normally transitions to a full connected socket upon receiving the final ACK. A critical race condition allows an unauthenticated attacker to free and reuse this memory via crafted packets before the transition completes, potentially leading to remote code execution or denial of service.

### Key Findings
- The vulnerability (CVE-2026-98432) is a use-after-free in tcp_v4_syn_recv_sock() where IP options are passed to a new child socket without being copied, creating a window for exploitation during the TCP handshake.
- Exploitation requires sending crafted IPv4 packets to a listening TCP socket and can trigger via the main path or request-socket migration, which is enabled by default settings or BPF programs.
- Detection telemetry should focus on network connections involving unusual IP option handling during initial SYN states, as the exploit targets public-facing applications with reachable IPv4 TCP listeners.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries are leveraging a published Proof-of-Concept exploit for CVE-2026-98432 to target Linux kernel vulnerabilities involving MPTCP and TCP options. The PoC enables the exploitation of a use-after-free condition via race conditions, potentially leading to remote code execution or privilege escalation on public-facing systems.

### Key Findings
- The exploit targets CVE-2026-98432, a Linux kernel vulnerability related to improper freeing of inet_opt and ireq_opt structures after RCU grace periods, classified with a CVSS score of 8.1 (Important).
- A functional PoC is available on GitHub (H1z3-br0/CVE-2026-98432) that utilizes race triggers and heap-reuse oracles to bypass KASLR and groom the heap for payload delivery.
- The tool supports multiple execution modes including vulnerability checking (--check), probing MPTCP listeners (--probe), and launching the actual race condition exploit (--race with specified workers and duration).
- Detection is facilitated by the PoC's built-in pcap analysis capabilities, allowing defenders to identify exploitation attempts through network packet captures using tools like analyze_pcap.py.
- EPSS data indicates a moderate/low probability of active exploitation (0.46%), but the availability of the PoC significantly increases the risk of automated in-the-wild attacks targeting exposed Linux services.
