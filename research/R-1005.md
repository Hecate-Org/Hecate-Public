## 1. System Research: How It Works

### Summary
PAN-OS GlobalProtect manages remote access VPN connections by exposing gateway and portal interfaces, where the system normally processes session identifiers (SESSID) to maintain user state. Under normal operation, these inputs are validated internally; however, a vulnerability in unpatched versions allows unsanitized cookie values to be passed directly to shell commands without proper neutralization of special elements.

### Key Findings
- The vulnerability is triggered when an attacker crafts malicious HTTP requests containing OS command metacharacters (e.g., backticks, $(...)) within the SESSID cookie header sent to /ssl-vpn/hipreport.esp or /global-protect/login.esp.
- Successful exploitation allows unauthenticated remote code execution with root privileges by spawning processes such as /bin/sh or /bin/bash via the web gateway processes (pan_comm, nginx, httpd).
- Adversaries exploit this access to establish persistence by writing malicious cron schedules to /etc/cron.d/ and deploy the UPSTYLE backdoor to harvest configuration credentials and active session tokens.
- Exfiltrated data is transmitted via outbound HTTPS connections or web-accessible staging paths, while detection relies on monitoring for unexpected files in /etc/cron.d/ or /var/appweb/sslvpndocs/ and abnormal process creation events.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit CVE-2024-3400, a critical command injection vulnerability in Palo Alto Networks PAN-OS GlobalProtect (versions 10.2, 11.0, and 11.1), to execute arbitrary Linux commands with root privileges via unauthenticated access to the /ssl-vpn/hipreport.esp endpoint. This technique enables immediate remote code execution on affected firewalls configured with GlobalProtect gateway or portal services.

### Key Findings
- The vulnerability (CVE-2024-3400) is a CVSS 10.0 critical arbitrary file-write/command injection flaw allowing unauthenticated Remote Code Execution (RCE) on PAN-OS versions 10.2, 11.0, and 11.1.
- Attackers primarily use the T1190 technique to exploit public-facing applications, specifically targeting the GlobalProtect interface which is often exposed to the internet.
- Exploitation results in the execution of arbitrary shell commands with root-level privileges (T1059.004), facilitating further persistence and lateral movement within the network.
- Threat intelligence indicates active exploitation by various threat actors, including Iranian APT groups, who leverage this vulnerability for initial access and subsequent malware deployment such as XMRig.
- Remediation requires updating PAN-OS to patched versions (e.g., 10.2.9-h1, 11.0.4-h1, or 11.1.2-h3) and applying vulnerability protection signatures to block exploitation attempts.

## 5. Research Synthesis

### Executive Summary
Adversaries are exploiting CVE-2024-3400, a critical unauthenticated command injection in Palo Alto Networks PAN-OS GlobalProtect, by injecting shell metacharacters into the SESSID cookie sent to /ssl-vpn/hipreport.esp. This allows root-level remote code execution via spawned shells (/bin/sh, /bin/bash) and subsequent persistence through malicious cron jobs in /etc/cron.d/. Detection requires correlating specific HTTP request anomalies with immediate child process creation events from web gateway processes.

### Recommended Hypothesis
> Adversaries use crafted SESSID cookies containing shell metacharacters sent to /ssl-vpn/hipreport.esp to execute arbitrary root-level commands via spawned shells on unpatched Palo Alto Networks PAN-OS GlobalProtect gateways

### Gaps Identified
- Lack of visibility into the content of encrypted HTTPS traffic between clients and the GlobalProtect portal prevents detection of the initial command injection payload (SESSID cookie) before it is processed by the gateway
- Standard endpoint telemetry may miss the rapid process tree where legitimate web processes (pan_comm, nginx) immediately spawn /bin/sh or bash to write files to /etc/cron.d/, as these events are short-lived and occur with root privileges often masked by system-level noise

### Key Findings
- Hypothesis: Adversaries use crafted SESSID cookies containing shell metacharacters sent to /ssl-vpn/hipreport.esp to execute arbitrary root-level commands via spawned shells on unpatched Palo Alto Networks PAN-OS GlobalProtect gateways
- Gap: Lack of visibility into the content of encrypted HTTPS traffic between clients and the GlobalProtect portal prevents detection of the initial command injection payload (SESSID cookie) before it is processed by the gateway
- Gap: Standard endpoint telemetry may miss the rapid process tree where legitimate web processes (pan_comm, nginx) immediately spawn /bin/sh or bash to write files to /etc/cron.d/, as these events are short-lived and occur with root privileges often masked by system-level noise
- Focus: Correlate HTTP access logs for requests to /ssl-vpn/hipreport.esp containing shell metacharacters (backticks, $(), semicolons) in the Cookie header with simultaneous process creation events of child shells from parent web processes
- Focus: Monitor file integrity changes in /etc/cron.d/ and /var/appweb/sslvpndocs/ for unexpected writes or modifications that align temporally with anomalous outbound HTTPS connections indicative of UPSTYLE backdoor communication
