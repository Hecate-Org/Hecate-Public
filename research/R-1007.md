## 1. System Research: How It Works

### Summary
PAN-OS GlobalProtect Gateway processes VPN client health check requests via the /ssl-vpn/hipreport.esp endpoint, accepting session cookies and HIP (Host Information Profile) data over HTTPS. The web gateway processes (pan_comm, nginx, or httpd) run with root privileges to enforce security policies and handle SSL VPN sessions, parsing HTTP headers including Cookie and SESSID values to maintain client state.

### Key Findings
- Normal GlobalProtect operation involves web gateway processes (pan_comm, nginx, httpd) handling HTTPS POST requests to /ssl-vpn/hipreport.esp and /global-protect/logout.esp endpoints, processing session cookies to validate VPN client connections.
- The gateway processes run with root privileges and execute shell commands to perform system-level operations, including reading configuration files, managing VPN tunnels, and enforcing security policies based on client HIP reports.
- Legitimate session management writes temporary files to /var/appweb/sslvpndocs/ for portal resources and images, and maintains logs showing client IP addresses, timestamps, HTTP methods, response codes, and request rates (typically measured per second).
- Standard telemetry includes HTTP access logs with format: client_IP [timestamp] HTTP_method /endpoint HTTP_version response_code bytes_transferred, along with task IDs and rate-limiting metrics for request monitoring.
- The GlobalProtect Gateway may spawn child processes including /bin/sh or /bin/bash for legitimate administrative tasks, system health checks, and integration with underlying PAN-OS management functions, though such spawning from web-facing processes warrants scrutiny.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit CVE-2024-3400, a command injection vulnerability in Palo Alto Networks PAN-OS GlobalProtect gateway, by sending crafted HTTP requests with malicious shell commands embedded in session cookies to the /ssl-vpn/hipreport.esp endpoint. Upon successful exploitation, the gateway executes arbitrary commands via /bin/sh or /bin/bash with root privileges, enabling attackers to deploy backdoors, establish persistence through cron jobs, and exfiltrate sensitive data including credentials and session tokens.

### Key Findings
- Attackers inject shell metacharacters (backticks, $(...), semicolons) into Cookie or SESSID headers of HTTP requests targeting /ssl-vpn/hipreport.esp to achieve unauthenticated remote code execution with root privileges
- The UPSTYLE backdoor is deployed post-exploitation to harvest configuration credentials, active session tokens, and system information from compromised PAN-OS devices
- Persistence is established by writing malicious cron schedules to /etc/cron.d/ (T1053.003) that regularly download secondary payloads
- Exfiltration occurs via outbound HTTPS connections (T1071.001) or through web-accessible staging paths such as /var/appweb/sslvpndocs/
- Detection opportunities include monitoring web gateway processes (pan_comm, nginx, httpd) spawning unexpected child processes like /bin/sh, curl, or bash, and detecting unauthorized file creation in /etc/cron.d/
- CVE-2024-3400 has a CVSS score of 10.0, is actively exploited in the wild with 100% EPSS exploit probability, and affects PAN-OS versions 10.2, 11.0, and 11.1 configured with GlobalProtect gateway or portal

## 3. Telemetry Mapping: OCSF Fields

### Summary
The source intelligence describes adversaries exploiting CVE-2024-3400 to inject shell commands via HTTP requests to PAN-OS GlobalProtect gateways. Detection focuses on three layers: (1) web server logs capturing malicious HTTP requests with shell metacharacters in cookies targeting /ssl-vpn/hipreport.esp, (2) process creation events showing web gateway processes spawning Unix shells (/bin/sh, /bin/bash) or utilities (curl) with root privileges, and (3) file system events detecting cron job creation in /etc/cron.d/ for persistence. This maps to T1059.004 (Unix Shell) for command execution, T1053.003 (Scheduled Task/Job: Cron) for persistence, and T1071.001 (Application Layer Protocol: Web Protocols) for C2 communication.

### Key Fields

OCSF path → the event field `knowledge/environment.md` documents for it.

- http_activity.url: Requests to /ssl-vpn/hipreport.esp endpoint where command injection occurs
- http_activity.http_request_header.cookie: Cookie or SESSID headers containing shell metacharacters (backticks, $(...), semicolons, pipes) used for command injection
- process.parent_process.name: Web gateway processes (pan_comm, nginx, httpd) that should not spawn shell processes
- process.file.name: Child processes /bin/sh, /bin/bash, curl, or wget spawned by web gateway indicating command execution
- file.path: File creation or modification in /etc/cron.d/ indicating scheduled task persistence (T1053.003)
- process.uid: Process execution context showing root (UID 0) privileges for injected commands

## 5. Research Synthesis

### Executive Summary
CVE-2024-3400 exploitation targets PAN-OS GlobalProtect gateways through command injection in /ssl-vpn/hipreport.esp requests, with shell metacharacters embedded in Cookie/SESSID headers triggering root-privileged execution via web gateway processes (pan_comm, nginx, httpd). Detection requires correlating three evidence layers: HTTP request inspection for injection payloads, process telemetry showing abnormal shell spawning from web processes, and file integrity monitoring for /etc/cron.d/ persistence artifacts. The UPSTYLE backdoor deployment and HTTPS-based exfiltration via /var/appweb/sslvpndocs/ staging paths represent post-exploitation phases requiring separate behavioral detection.

### Recommended Hypothesis
> Adversaries use crafted HTTP requests containing shell metacharacters in Cookie/SESSID headers targeting /ssl-vpn/hipreport.esp to achieve unauthenticated command execution with root privileges on PAN-OS GlobalProtect gateways, establishing persistence via /etc/cron.d/ and deploying backdoors for credential harvesting

### Gaps Identified
- HTTP request header inspection depth—if http_activity.http_request_header.cookie field does not preserve raw cookie values or truncates long headers, shell metacharacters (backticks, $(...), semicolons) embedded in SESSID may be lost before analysis, preventing detection of injection payloads at the entry point
- Process telemetry completeness on PAN-OS appliances—uncertain whether EDR/process creation events are collected from GlobalProtect gateway appliances themselves, as these are network security devices rather than traditional endpoints; missing parent-child process relationships between pan_comm/nginx/httpd and /bin/sh would eliminate primary execution detection
- File integrity monitoring scope—unclear if /etc/cron.d/ and /var/appweb/sslvpndocs/ paths on PAN-OS appliances generate file creation/modification events in available telemetry, and whether retention covers the persistence window between initial exploitation and cron execution

### Key Findings
- Hypothesis: Adversaries use crafted HTTP requests containing shell metacharacters in Cookie/SESSID headers targeting /ssl-vpn/hipreport.esp to achieve unauthenticated command execution with root privileges on PAN-OS GlobalProtect gateways, establishing persistence via /etc/cron.d/ and deploying backdoors for credential harvesting
- Gap: HTTP request header inspection depth—if http_activity.http_request_header.cookie field does not preserve raw cookie values or truncates long headers, shell metacharacters (backticks, $(...), semicolons) embedded in SESSID may be lost before analysis, preventing detection of injection payloads at the entry point
- Gap: Process telemetry completeness on PAN-OS appliances—uncertain whether EDR/process creation events are collected from GlobalProtect gateway appliances themselves, as these are network security devices rather than traditional endpoints; missing parent-child process relationships between pan_comm/nginx/httpd and /bin/sh would eliminate primary execution detection
- Gap: File integrity monitoring scope—unclear if /etc/cron.d/ and /var/appweb/sslvpndocs/ paths on PAN-OS appliances generate file creation/modification events in available telemetry, and whether retention covers the persistence window between initial exploitation and cron execution
- Focus: Validate http_activity telemetry availability from PAN-OS GlobalProtect gateways, specifically testing whether Cookie header contents are ingested with full fidelity for requests to /ssl-vpn/hipreport.esp, and establish baseline request patterns (normal HIP report submissions vs. anomalous cookie lengths/character sets)
- Focus: Hunt for process creation events where parent_process.name matches (pan_comm OR nginx OR httpd) AND process.file.name matches (/bin/sh OR /bin/bash OR curl OR wget), then correlate with network connections to distinguish legitimate gateway operations from post-exploitation tool downloads or reverse shells
- Focus: Enumerate file creation events in /etc/cron.d/ and /var/appweb/sslvpndocs/ paths on PAN-OS devices, prioritizing unexpected cron job schedules created outside maintenance windows and web-accessible files written by web gateway processes rather than legitimate update mechanisms
