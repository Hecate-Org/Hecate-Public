# R-0974: APT41 Enterprise Intrusion: LSASS Memory Dumping via Comsvcs DLL Research

**Topic:** APT41 Enterprise Intrusion: LSASS Memory Dumping via Comsvcs DLL
**MITRE ATT&CK:** T1003.001
**Duration:** 2.0 minutes

---

## 1. System Research: How It Works

### Summary
The legitimate comsvcs.dll library contains a MiniDump export function that allows any process with appropriate privileges to write a detailed memory dump of a target process to disk. Adversaries abuse this functionality by invoking the DLL via rundll32.exe, specifying the LSASS process ID and output file path, thereby extracting credential material without deploying third-party tools.

### Key Findings
- The technique leverages the legitimate system library C:\windows\system32\comsvcs.dll and its exported MiniDump function, enabling memory dumping with SYSTEM privileges without downloading external binaries.
- Execution is typically performed via rundll32.exe using the command structure 'rundll32 <path_to_comsvcs.dll>,MiniDump {LSASS_PID} <output_file> full' to target the Local Security Authority Subsystem Service (LSASS).
- This method falls under MITRE ATT&CK technique T1003.001 (OS Credential Dumping: LSASS Memory) and is classified as 'Living off the Land' because it utilizes native Windows components for credential access.
- The resulting memory dump file contains sensitive credential material, such as plaintext passwords and NTLM hashes, which adversaries can subsequently extract to maintain persistence or move laterally within the enterprise infrastructure.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries, specifically identified as APT41 in the provided research context, abuse the legitimate Windows library comsvcs.dll to dump LSASS process memory and harvest credential material. This technique allows actors to obtain authentication data for lateral movement while attempting to evade detection by leveraging built-in system binaries rather than third-party tools.

### Key Findings
- APT41 utilizes the MiniDump function exported by comsvcs.dll, invoked via rundll32.exe, to perform credential dumping from LSASS memory (T1003.001).
- This intrusion campaign involves multiple concurrent techniques, including living-off-the-land execution via powershell.exe (T1059.001) and persistence through scheduled tasks executing rundll32.exe.
- The threat actor maintains command and control communications by sending beacons over HTTPS to the IP address 198.51.100.24, which is identified as a reserved/private test range rather than active adversary infrastructure in secondary enrichment.
- Secondary OSINT data confirms that comsvcs.dll is a documented LOLBAS capability for dumping LSASS, with detection guidance available from vendors like Splunk and Elastic regarding its misuse via rundll32.
- While the primary source focuses on APT41's use of comsvcs.dll, external search results also note that other actors such as Volt Typhoon have utilized outdated versions of this DLL for similar credential access operations.

## 3. Telemetry Mapping: OCSF Fields

### Summary
The source intelligence confirms adversary behavior involving LSASS memory dumping via comsvcs.dll and persistence via scheduled tasks. Telemetry must capture the process creation event for rundll32.exe invoking comsvcs.dll MiniDump with the target LSASS PID, as well as the process creation event for schtasks.exe used to create persistent scheduled tasks.

### Key Fields

OCSF path → the event field `knowledge/environment.md` documents for it.

- process_creation.Image: Capture paths ending in \rundll32.exe when executing the comsvcs.dll MiniDump technique.
- process_creation.CommandLine: Capture arguments containing 'comsvcs.dll', 'MiniDump', and a process ID to identify LSASS dumping activity.
- process_access.TargetImage: Identify reads against \lsass.exe with GrantedAccess values indicating memory dump capabilities (e.g., 0x1010).
- process_creation.Image: Capture paths ending in \schtasks.exe for persistence mechanism detection.
- process_creation.CommandLine: Capture arguments containing '/create' to identify new scheduled task creation events.

## 5. Research Synthesis

### Executive Summary
APT41 leverages the native comsvcs.dll MiniDump export to extract credential material from LSASS memory, enabling lateral movement via living-off-the-land execution. Detection requires correlating rundll32.exe process creation with specific command-line arguments targeting LSASS PIDs alongside schtasks.exe persistence mechanisms.

### Recommended Hypothesis
> Adversaries use rundll32.exe to invoke comsvcs.dll MiniDump on lsass.exe to harvest credentials for lateral movement via scheduled tasks

### Gaps Identified
- Standard EDR process monitoring often fails to correlate the parent-child relationship between rundll32.exe and the subsequent schtasks.exe execution if they occur in separate, non-linked threads or sessions.
- Network telemetry may miss C2 beacons if the communication is encrypted over HTTPS to a reserved IP range (198.51.100.24) that does not trigger standard DLP alerts for external malicious infrastructure.

### Key Findings
- Hypothesis: Adversaries use rundll32.exe to invoke comsvcs.dll MiniDump on lsass.exe to harvest credentials for lateral movement via scheduled tasks
- Gap: Standard EDR process monitoring often fails to correlate the parent-child relationship between rundll32.exe and the subsequent schtasks.exe execution if they occur in separate, non-linked threads or sessions.
- Gap: Network telemetry may miss C2 beacons if the communication is encrypted over HTTPS to a reserved IP range (198.51.100.24) that does not trigger standard DLP alerts for external malicious infrastructure.
- Focus: Monitor process creation events for rundll32.exe invoking 'MiniDump' with 'comsvcs.dll' and extract the specific LSASS PID from the command line arguments.
- Focus: Correlate successful LSASS memory access grants (e.g., 0x1010) with subsequent scheduled task creations using schtasks.exe to identify post-exploitation persistence.
