## 1. System Research: How It Works

### Summary
GitLab provides CI/CD orchestration services where users submit configuration files containing regular expressions to define pipeline behaviors. A critical vulnerability in this process allows unauthenticated attackers to exploit integer overflow flaws within the regex engine to achieve arbitrary code execution on the server.

### Key Findings
- The primary attack vector involves submitting a specially crafted regular expression within a CI/CD configuration file, which triggers an integer overflow or wraparound error due to insufficient validation.
- The vulnerability is unauthenticated (CVSS AV:N, PR:N), allowing any user to exploit it without credentials, leading to full system compromise with a CVSS score of 10.0.
- Secondary threat intelligence links the exploitation to the 'ARMORY CASTLE' adversary group and associated tags such as 'bareclaw' and 'sawfly', indicating active targeted campaigns.
- While not evidence of use in this specific incident, documented capabilities exist for using legitimate tools like VS Code (code.exe) or Url.dll to establish reverse shells or load payloads if the initial vulnerability is successfully exploited.

## 5. Research Synthesis

### Executive Summary
CVE-2026-97229 enables unauthenticated arbitrary code execution on GitLab via integer overflow in CI/CD regex validation, actively exploited by the ARMORY CASTLE threat group. Detection must prioritize identifying malicious regex patterns submitted to CI/CD pipelines and subsequent post-exploitation artifacts such as C2 beacons or LOLBIN usage.

### Recommended Hypothesis
> Adversaries use specially crafted regular expressions in unauthenticated GitLab CI/CD configurations to trigger integer overflow vulnerabilities, achieving arbitrary code execution on the server to establish persistent access.

### Gaps Identified
- Lack of visibility into raw regex payload content submitted via GitLab's API or web interfaces prevents detection of the specific malicious input strings triggering the integer overflow before execution occurs.
- Absence of correlation between CI/CD job logs and endpoint process creation telemetry obscures the transition from vulnerability exploitation to initial access, particularly if attackers utilize legitimate binaries like code.exe or url.dll for lateral movement or C2.

### Key Findings
- Hypothesis: Adversaries use specially crafted regular expressions in unauthenticated GitLab CI/CD configurations to trigger integer overflow vulnerabilities, achieving arbitrary code execution on the server to establish persistent access.
- Gap: Lack of visibility into raw regex payload content submitted via GitLab's API or web interfaces prevents detection of the specific malicious input strings triggering the integer overflow before execution occurs.

- Focus: Monitor GitLab API logs and CI/CD configuration uploads for anomalous regex patterns characterized by excessive quantifiers, nested groups, or unusual character classes indicative of ReDoS or integer overflow triggers.
