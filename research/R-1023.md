## 1. System Research: How It Works

### Summary
CVE-2026-98260 is a Linux kernel use-after-free vulnerability exploitable by local users through POSIX CPU timer manipulation during execve() calls. The jonrazta89/OneSamAKAGhostKey repository contains an Android-focused proof-of-concept that builds an APK (com.EternalTimes.GhostKey) with native exploit code compiled into libcve98260.so, utilizing device-specific kernel profiles derived from boot.img files.

### Key Findings
- The exploit is packaged as an Android application (GhostKey APK) with package names com.EternalTimes.GhostKey (release) and com.EternalTimes.GhostKey.test (testing), built using Gradle (./gradlew assembleRelease) and signed with app/keystore/release.keystore
- Native exploit code is compiled into libcve98260.so via NDK/CMake and requires device-specific configuration profiles generated by tool/mkprofile.py from boot.img files, stored in app/src/main/assets/device_profiles/
- Runtime artifacts are created in /data/local/tmp/cve98260-app/ including log files, kallsyms.txt (kernel symbol table), and an allow_shell control file that must be set to 1 for shell-based execution
- The vulnerability involves creating and arming a POSIX CPU timer on a non-leader thread, then triggering execve() failure after de_thread() but before timer cleanup, resulting in a use-after-free condition with a controlled 8-byte write via rb_erase()
- Microsoft released a patch on 2026-10-07 with CVSS 5.5 (CVSS:3.1/AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H), and EPSS scoring shows 0.18% exploit probability as of 2026-11-13, though at least 42 public PoC exploits exist

## 2. Adversary Tradecraft: Attack Techniques

### Summary
CVE-2026-98260 is a use-after-free vulnerability in the Linux kernel's POSIX timer cleanup process that allows a local attacker to execute arbitrary code with elevated privileges. The vulnerability is triggered when a non-leader thread creates and arms a POSIX CPU timer, then calls execve() in a way that causes execution to fail after de_thread(), leading to memory corruption. Multiple public proof-of-concept exploits exist, including Android-focused implementations that achieve root access.

### Key Findings
- The vulnerability has a CVSS score of 7.8 HIGH with local attack vector (AV:L) requiring low privileges (PR:L), allowing escalation to high confidentiality, integrity, and availability impact
- At least 42 public PoC exploits are available, including Android-specific implementations (GhostKey APK) that integrate 'ghostlock-s26 post-UAF' techniques and device-specific profiles generated from boot.img files
- Exploitation tooling includes native libraries (libcve98260.so) compiled via NDK/CMake, Gradle-based APK assembly, and Python scripts for device profile generation (mkprofile.py), with artifacts stored in /data/local/tmp/cve98260-app/
- The exploit achieves uid-0 (root) shell access on Android devices through credential manipulation techniques, with multiple repositories (janewas, 4627488/cve-2026-98260-nezha, woshigenm/CVE-2026-98260) demonstrating functional exploits including Shizuku-based implementations
- EPSS scoring indicates 0.18% exploit probability (8.2th percentile), though the vulnerability is not listed in VulnCheck KEV, suggesting no confirmed widespread exploitation in the wild despite public PoC availability
- Mitigation involves applying the kernel patch that moves POSIX timer cleanup immediately after de_thread() and restricting local user access, as the vulnerability requires local execution context
