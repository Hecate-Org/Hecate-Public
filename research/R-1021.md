## 1. System Research: How It Works

### Summary
UnrealIRCd is an open-source Internet Relay Chat (IRC) server that facilitates communication across networks by linking multiple servers together. It functions as a central hub for relayed text-based messaging, supporting thousands of networks across Linux, OS X, and Windows operating systems.

### Key Findings
- The system relies on inter-server communication protocols where linked servers exchange commands, which creates an attack vector if delimiter neutralization fails between nodes.
- Network traffic typically occurs over standard IRC ports (e.g., port 6667), which can be probed using Nmap scripts like 'irc-unrealircd-backdoor.nse' to detect improper handling of injected server-to-server commands.
- The software is a widely deployed open-source service running on major desktop and server operating systems, including Linux, OS X, and Windows.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit an improper neutralization of delimiters vulnerability in UnrealIRCd to inject and execute server-to-server commands with server authority, affecting networks with two or more linked servers. This flaw allows any connected user to run arbitrary commands, potentially escalating privileges to gain full control over the compromised server.

### Key Findings
- The vulnerability (CVE-2026-114713) is actively exploited in the wild, allowing attackers to inject server-to-server commands that are executed with elevated server authority.
- Exploitation requires the target network to have two or more linked servers, enabling command injection across the IRC infrastructure.
- Historically, this class of vulnerability has been abused via backdoored versions of UnrealIRCd (e.g., version 3.2.8.1) that disguise command execution as debug statements, allowing arbitrary commands starting with specific prefixes like 'AB'.
- Attackers have utilized the Nmap Scripting Engine (irc-unrealrcd-backdoor.nse) to demonstrate exploitation, such as invoking remote downloads and establishing reverse shells.
- Mitigation requires upgrading to the latest patched version of UnrealIRCd and removing any compromised instances, in accordance with CISA KEV and BOD 26-04 guidance.

## 5. Research Synthesis

### Executive Summary
CVE-2026-114713 enables authenticated IRC users on multi-server UnrealIRCd networks to inject server-to-server protocol commands with elevated authority by exploiting improper delimiter neutralization. Historical exploitation patterns involve backdoored UnrealIRCd versions (3.2.8.1) accepting debug-prefixed commands for arbitrary code execution, detectable via network traffic analysis and process execution monitoring. Detection requires visibility into IRC protocol traffic patterns, server-to-server command flows, and correlation of unexpected child processes spawned from UnrealIRCd daemon contexts.

### Recommended Hypothesis
> Adversaries use IRC protocol delimiter injection on UnrealIRCd servers to execute arbitrary server-to-server commands with elevated authority, enabling privilege escalation and remote code execution on linked IRC networks.

### Gaps Identified
- IRC application-layer protocol traffic is typically not parsed or logged by standard network monitoring, preventing visibility into injected server-to-server commands, delimiter manipulation attempts, or anomalous protocol sequences between linked servers.
- UnrealIRCd process execution telemetry may not distinguish legitimate server operations from injected commands spawning child processes (shells, downloaders, reverse connections), especially if process ancestry and command-line arguments are not captured for IRC daemon contexts.
- Network perimeter visibility into IRC ports (6667, 6697, custom ports) may be limited if servers are internet-facing or in DMZ segments where packet capture, flow logs, or deep packet inspection are not deployed or retained.

### Key Findings
- Hypothesis: Adversaries use IRC protocol delimiter injection on UnrealIRCd servers to execute arbitrary server-to-server commands with elevated authority, enabling privilege escalation and remote code execution on linked IRC networks.
- Gap: IRC application-layer protocol traffic is typically not parsed or logged by standard network monitoring, preventing visibility into injected server-to-server commands, delimiter manipulation attempts, or anomalous protocol sequences between linked servers.
- Gap: UnrealIRCd process execution telemetry may not distinguish legitimate server operations from injected commands spawning child processes (shells, downloaders, reverse connections), especially if process ancestry and command-line arguments are not captured for IRC daemon contexts.
- Gap: Network perimeter visibility into IRC ports (6667, 6697, custom ports) may be limited if servers are internet-facing or in DMZ segments where packet capture, flow logs, or deep packet inspection are not deployed or retained.
- Focus: Query network connection logs and process execution events for UnrealIRCd daemon processes spawning unexpected child processes (bash, sh, wget, curl, nc, python) that indicate command injection exploitation, correlating with external network connections from those children.
- Focus: Identify UnrealIRCd server instances listening on standard IRC ports through asset inventory, vulnerability scanning (Nmap irc-unrealircd-backdoor script), and version enumeration to scope exposure, prioritizing multi-server linked configurations per the exploitation prerequisite.
- Focus: Analyze netflow or firewall logs for IRC port traffic patterns showing server-to-server communication followed by anomalous outbound connections (reverse shells, C2 beaconing) or inbound file transfers from UnrealIRCd server hosts, establishing behavioral baselines for legitimate inter-server linking first.
