## 1. System Research: How It Works

### Summary
GPUStack is an open-source GPU cluster manager for AI model serving and GPU-instance provisioning that exposes an HTTP API for administrative functions. Under normal operation, the authentication module (gpustack/api/auth.py) validates incoming requests, with the get_current_user function determining caller identity based on TCP peer address and optional X-GPUStack-Real-IP headers before granting access to endpoints like /v2/inference-backends/from-yaml.

### Key Findings
- GPUStack API authentication logic in gpustack/api/auth.py evaluates the force_auth_localhost configuration flag (default: false) and TCP peer source address to determine whether to grant built-in administrator privileges to loopback (127.0.0.1) connections without credential validation.
- Administrative API endpoints accept requests for user/model/worker enumeration and modification, persistent administrator API-key creation via dedicated endpoints, and YAML-based inference backend configuration through POST /v2/inference-backends/from-yaml which can execute arbitrary code.
- The API processes X-GPUStack-Real-IP headers to identify the original client IP when deployed behind reverse proxies, creating a trust boundary where header values influence authentication decisions for loopback-sourced requests.
- Worker and cloud-provider secrets are accessible through authenticated API calls, stored within the GPUStack configuration and retrievable by administrative users through enumeration endpoints.
- Network telemetry for legitimate GPUStack deployments includes HTTP/HTTPS traffic to the API server (typically listening on standard ports), with reverse proxy deployments showing loopback TCP connections (127.0.0.1) between the proxy and GPUStack backend service.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
CVE-2026-102895 is an improper authentication vulnerability in GPUStack that allows unauthenticated remote attackers to gain administrative privileges without any prior authentication. Adversaries exploit this flaw to modify users and AI models, create persistent administrator API keys, disclose worker and cloud-provider secrets, and execute arbitrary code through the POST /v2/inference-backends/from-yaml endpoint.

### Key Findings
- The vulnerability permits complete unauthenticated administrative access to GPUStack deployments, with a CVSS score of CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H indicating network-accessible exploitation requiring no privileges or user interaction
- Active in-the-wild exploitation has been confirmed by VulnCheck KEV and AlienVault OTX, with CISA adding it to the Known Exploited Vulnerabilities catalog on 2026-11-09
- Attack capabilities include modifying users and AI models, creating persistent administrator API keys for long-term access, and disclosing sensitive worker and cloud-provider credentials
- Remote code execution is achievable through the POST /v2/inference-backends/from-yaml endpoint, allowing attackers to execute arbitrary code on compromised systems
- The vulnerability is related to authentication bypass via trusted loopback source mechanisms involving reverse-proxy TCP peer or X-GPUStack-Real-IP header manipulation, affecting GPUStack through version 2.2.1
- EPSS scoring indicates 0.56% exploit probability (46.7th percentile) as of 2026-11-10, though active exploitation contradicts the moderate automated prediction

## 5. Research Synthesis

### Executive Summary
CVE-2026-102895 enables unauthenticated remote administrative access to GPUStack through authentication bypass exploiting trusted loopback source logic and X-GPUStack-Real-IP header manipulation, confirmed exploited in-the-wild per CISA KEV. Adversaries leverage this to create persistent API keys, exfiltrate worker/cloud-provider secrets, and achieve RCE via POST /v2/inference-backends/from-yaml YAML injection. Detection requires correlating reverse-proxy header presence with administrative API calls, monitoring for unauthenticated session elevation to admin privileges, and identifying spawned processes from GPUStack workers executing cloud/container orchestration commands.

### Recommended Hypothesis
> Adversaries use X-GPUStack-Real-IP header injection or reverse-proxy source IP spoofing to bypass authentication checks in gpustack/api/auth.py get_current_user function, gaining unauthenticated administrative access to GPUStack API endpoints for persistent API key creation, secret disclosure, and code execution via /v2/inference-backends/from-yaml YAML injection on internet-exposed GPUStack deployments.

### Gaps Identified
- Lack of visibility into HTTP header manipulation patterns where X-GPUStack-Real-IP or similar reverse-proxy trust headers contain loopback/RFC1918 addresses while originating from external source IPs, particularly when correlated with successful administrative authentication decisions without Bearer token validation.
- Insufficient telemetry capturing the authentication decision flow in GPUStack's get_current_user function, specifically the force_auth_localhost flag evaluation and TCP peer address trust logic that grants built-in administrator privileges, preventing detection of privilege escalation from unauthenticated to admin context within a single HTTP request.
- Limited process execution monitoring for YAML deserialization and injection artifacts, specifically child processes spawned by GPUStack worker services executing kubectl, docker, cloud provider CLIs, or arbitrary shell commands following POST requests to /v2/inference-backends/from-yaml with suspicious YAML payloads containing exec/command directives.

### Key Findings
- Hypothesis: Adversaries use X-GPUStack-Real-IP header injection or reverse-proxy source IP spoofing to bypass authentication checks in gpustack/api/auth.py get_current_user function, gaining unauthenticated administrative access to GPUStack API endpoints for persistent API key creation, secret disclosure, and code execution via /v2/inference-backends/from-yaml YAML injection on internet-exposed GPUStack deployments.
- Gap: Lack of visibility into HTTP header manipulation patterns where X-GPUStack-Real-IP or similar reverse-proxy trust headers contain loopback/RFC1918 addresses while originating from external source IPs, particularly when correlated with successful administrative authentication decisions without Bearer token validation.
- Gap: Insufficient telemetry capturing the authentication decision flow in GPUStack's get_current_user function, specifically the force_auth_localhost flag evaluation and TCP peer address trust logic that grants built-in administrator privileges, preventing detection of privilege escalation from unauthenticated to admin context within a single HTTP request.
- Gap: Limited process execution monitoring for YAML deserialization and injection artifacts, specifically child processes spawned by GPUStack worker services executing kubectl, docker, cloud provider CLIs, or arbitrary shell commands following POST requests to /v2/inference-backends/from-yaml with suspicious YAML payloads containing exec/command directives.
- Focus: Develop detection logic for HTTP requests to GPUStack administrative endpoints (/v2/users, /v2/api-keys, /v2/models, /v2/inference-backends/from-yaml) originating from external IPs that contain X-GPUStack-Real-IP headers with loopback/internal addresses and result in successful 200/201 responses without valid Authorization Bearer tokens in the request headers.
- Focus: Hunt for anomalous API key creation events via /v2/api-keys POST requests from sessions that lack prior successful authentication events, correlating with subsequent API calls using newly-created keys to enumerate workers, access cloud-provider secrets, or modify inference backend configurations.
- Focus: Investigate process execution chains where GPUStack worker processes spawn unexpected child processes (kubectl, docker, aws/gcloud/az CLIs, curl, wget, bash/sh) within temporal proximity to POST /v2/inference-backends/from-yaml requests, focusing on command-line arguments containing base64-encoded payloads, remote script downloads, or reverse shell patterns.
