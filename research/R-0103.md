## 1. System Research: How It Works

### Summary
The OnePlus 16 (PYB110) device runs an Android 16 (Linux kernel 6.12 / 6.18) environment secured by ColorOS / OxygenOS platform guardrails. Under standard operation, device integrity is defended by OPlus-proprietary daemons and kernel mechanisms:
- `com.oplus.exsystemservice`: A core Android framework service that monitors root markers, system partition integrity, and unauthorized debugger / SU hooks.
- `vendor.oplus.hardware.riskdetect.IRiskDetect/default` (`riskdetect` service): A hardware HAL service providing real-time anti-root detection. When root escalation is confirmed, `exsystemservice` issues an immediate forced system reboot via `reboot("Malicious app try to root devices")` within a 15-second grace period.
- `oplus_secure_guard_new`: A vendor-specific kernel module enforcing access controls and restricting unauthorized kernel module injection.

### Key Findings
- **Vulnerability Root Cause (CVE-2026-64560):** A race condition exists within the Linux kernel POSIX CPU timers subsystem (`kernel/time/posix-cpu-timers.c`). When `exec()` is invoked by a non-thread-group-leader thread, timer cleanup and thread group deallocation can desynchronize, triggering a Use-After-Free (UAF) condition on `posix_cputimer_base`.
- **Credential Corruption Primitive:** The weaponized exploit grooms kernel heap allocations (via SLUB allocator heap spraying) to reclaim the freed timer structure. By manipulating adjacent memory fields, the exploit overwrites the calling thread's `struct cred` pointer with a synthesized credential structure (`uid=0`, `gid=0`, permissive capabilities), achieving full kernel privilege escalation.
- **Root Daemon & IPC Hand-off:** Privilege escalation is coordinated through a standalone Rust/C binary (`t98260` / `t61269`), which instantiates a local Unix domain socket listener at `/data/local/tmp/t61269-root.sock` to serve root commands to client processes (`t61269_su`).

## 2. Adversary Tradecraft: Attack Techniques

### Summary
The `OnePlus16-Jailbreak` package combines local kernel privilege escalation (CVE-2026-64560) with rootkit deployment and vendor anti-root mitigation bypass. The attack sequence operates in five orchestrated phases:

1. **Staging & Compilation:** The adversary builds an exploit application using Gradle (`./gradlew :app:assembleRelease`, `./gradlew :app:assembleDebug`) with signing configurations (`keystore.properties.example`). Assets containing compiled exploit binaries (`t98260`, `t61269`) and pre-compiled Linux Kernel Modules (`susfs_guard_lkm-android16-6.12.ko`) are packaged within `app/app/src/main/assets/pyb110/`.
2. **Exploitation (CVE-2026-64560):** The app stages binaries into `/data/local/tmp/pyb110-<boot_id>-<epoch>/` and invokes the Rust orchestrator `t98260`. The C plant triggers the timer UAF race condition, waits for memory page release (`mm_page_free`), sprays allocations, and writes fake credentials.
3. **Anti-Root Evasion:** To avoid detection by ColorOS security services and prevent the 15-second forced reboot (`reboot("Malicious app try to root devices")`), the exploit immediately unloads the vendor kernel module via `rmmod oplus_secure_guard_new` and continuously halts the risk detection service (`stop riskdetect` / `su -c 'stop riskdetect'`).
4. **KernelSU & SUSFS Injection:** The exploit injects the SUSFS kernel extension (`insmod susfs_guard_lkm-android16-6.12.ko` or `/data/adb/ksud insmod`), verifying successful load via `/sys/module/susfs_guard_lkm`, `/proc/susfs_kstat`, and `/proc/susfs_path`.
5. **Manager Deployment & Cleanup:** Drops and installs `KernelSU_v3.3.1-27-gdb6263d3_32707-release.apk`, writes a retirement sentinel (`/data/local/tmp/t61269-retire`), restores non-malicious system services (`com.oplus.screenshot` via `pm enable --user 0`), and restarts Zygote (`setprop ctl.restart zygote`).

## 5. Research Synthesis

### Executive Summary
CVE-2026-64560 represents a high-impact local privilege escalation vulnerability in the Linux kernel POSIX timer subsystem. When combined with manufacturer-specific evasion techniques against OPlus daemons (`com.oplus.exsystemservice`, `riskdetect`), it permits complete compromise of OnePlus 16 devices. Detection must emphasize host-based behavioral rules detecting anti-root service disabling, unauthorized kernel module injection (`susfs_guard_lkm`), and anomalous Unix domain socket creation in `/data/local/tmp/`.

### Recommended Hypothesis
> Adversaries exploit the CVE-2026-64560 Linux kernel POSIX CPU timer race condition and deploy custom kernel modules (`susfs_guard_lkm`) to disable manufacturer anti-root safeguards (`com.oplus.exsystemservice`, `riskdetect`) and establish persistent root access on OnePlus 16 Android devices.

### Gaps Identified
- Endpoint detection agents on mobile/Android devices often lack visibility into low-level Android HAL calls (`vendor.oplus.hardware.riskdetect`) or service manipulation (`stop riskdetect`).
- Kernel module insertions via raw syscalls or memory loading may bypass standard userspace command logging unless audited by Linux auditd/eBPF telemetry.
