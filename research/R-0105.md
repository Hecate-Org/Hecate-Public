# R-0105: CVE-2025-29927 - Next.js Middleware Authorization Bypass Research

**Topic:** CVE-2025-29927 - Next.js Middleware Authorization Bypass via `x-middleware-subrequest`  
**MITRE ATT&CK:** T1190 (Exploit Public-Facing Application)  
**Duration:** 3.5 minutes  

> **Independent web-grounded research.** Corroborated with active threat intelligence from Datadog Security Labs, JFrog Security, and Zscaler ThreatLabz regarding in-the-wild exploitation vectors.

---

## 1. System Research: How It Works

### Summary
Next.js applications utilize Middleware functions (`middleware.ts` / `middleware.js`) running on the edge or Node.js runtime to enforce authorization boundaries, route rewriting, session verification, and request filtering before requests reach page handlers or API endpoints. To prevent infinite recursive execution when middleware performs internal rewrites or subrequests, the Next.js `runMiddleware` function checks for an internal control header: `x-middleware-subrequest`. 

In unpatched versions (Next.js < 14.2.25 and Next.js < 15.0.0-rc.5), Next.js failed to strip or validate whether `x-middleware-subrequest` originated from an internal subrequest or an external untrusted client request. When an external client presents this header, the server skips middleware execution entirely, processing the request as if it had already been approved.

### Key Findings
- **Vulnerability Identifier:** CVE-2025-29927 (GHSA-f82v-jwr5-mffw, CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N - CVSS Score: 9.1 Critical).
- **Core Mechanism:** Inclusion of the custom `x-middleware-subrequest` HTTP request header causes `runMiddleware` to assume middleware has already executed, bypassing all authentication and authorization barriers on protected paths (such as `/api/admin/*`, `/dashboard/*`).
- **Exploitation Impact:** Unauthenticated remote attackers can directly reach restricted APIs, export sensitive data, and trigger administrative functions without valid session tokens or credentials.
- **Affected Packages:** Next.js versions 12.x, 13.x, 14.x prior to 14.2.25, and 15.x prior to 15.0.0-rc.5.

## 2. Adversary Tradecraft: Attack Techniques

### Summary
Adversaries exploit CVE-2025-29927 (T1190) by crafting inbound HTTP requests that inject `x-middleware-subrequest` headers. Automated scanners and weaponized exploit tools append this header during automated directory enumeration and endpoint fuzzing against internet-facing web assets to discover unprotected backend routes.

### Key Findings
- **In-the-Wild Exploitation:** VulnCheck KEV confirms active in-the-wild automated exploitation, and EPSS predicts a **99.22% probability** of exploitation.
- **Primary Attack Signature:**
  - HTTP Request Header: `x-middleware-subrequest` (values observed: `1`, `true`, `subrequest`, or arbitrary string payloads).
  - Target Endpoints: Privileged internal routes typically protected by middleware, such as `/api/admin/`, `/admin`, `/private/`, `/dashboard/`.
- **Public PoC Context vs. Production Threats:**
  - Initial public PoC repositories (such as the NTU student project `ntu-se6013-nextjs-auth-bypass`) bundled exploit verification inside Python `unittest` suites (`python3 -m unittest discover -s tests -v`).
  - While test harness commands run on the attacker's client workstation, production defenders must focus sensor visibility on inbound HTTP headers and reverse proxy logs rather than host process execution on Node.js application servers.

## 5. Research Synthesis

### Executive Summary
CVE-2025-29927 enables trivial, unauthenticated authorization bypass across vulnerable Next.js deployments through a single custom HTTP header: `x-middleware-subrequest`. High-confidence detection is best achieved at the reverse proxy or WAF layer by flagging or blocking any external incoming request containing this header.

### Recommended Hypothesis
> Adversaries supply crafted `x-middleware-subrequest` HTTP request headers to public-facing Next.js applications to bypass middleware authorization checks and gain unauthorized access to protected endpoints via CVE-2025-29927.

### Gaps Identified
- Access logs that strip or omit custom HTTP request headers fail to capture the bypass signature; reverse proxies must be configured to log incoming request headers (`cs-headers` / `$http_x_middleware_subrequest`).
- Host-only endpoint monitoring on the web server will not observe process execution anomalies because Next.js handles the exploit as legitimate Node.js application traffic.
